# Domain glossary

Vocabulary that the codebase should use consistently. Add a term here the first time you reach for it in a Module name, public function, or schema field.

## Brokerage data shape

**Holdings**
The advisor-facing view of what a client owns. A Holdings table has one row per Lot or one row per Position depending on the source — see Lot and Position. Stored as a typed SQLite table by `services.financial.holdings_store.HoldingsStore`.

**Lot**
A single tax lot — one acquisition of a security, with its own cost basis, acquisition date, and quantity. Pershing CSVs are typically lot-level.

**Position**
The aggregated holding of one security across all of a client's lots. Sum of lot quantities, sum of cost basis, weighted-average unit cost. The `<table>__by_symbol` view in HoldingsStore rolls Lots up to Positions.

**Account**
A single brokerage account (IRA, TOD, Joint, Variable Annuity, etc.). One client typically has multiple Accounts; reports may roll up across them or break them out.

**Household**
One client relationship, possibly spanning multiple Accounts and individuals (e.g. Bob and Linda Henderson).

## Ingest

**Vendor Profile**
Vendor- and format-specific knowledge about a brokerage export — how to identify the file (filename pattern + column hints), which preprocessing it needs (e.g. NetX360 hierarchical flattening), and what type or role overrides to apply during ingest. Lives under `services/ingest_profiles/`.

**Role** (column role)
The semantic meaning of a column in a Holdings table — e.g. `ticker`, `cusip`, `market_value`, `cost_basis`, `quantity`, `sector`. Detected by regex (`heuristic`), set by a Vendor Profile (`profile`), or proposed by an LLM pass (`llm`); the `role_source` field records which of these supplied it.

**Type extension**
A custom column type recognised during inference (e.g. `currency`, `percent`) that needs format-aware detection and coercion beyond the generic numeric/date/boolean/text types in `services.tabular.inference`. Currency and percent are built into HoldingsStore.

## Output

**Meeting Brief**
The one-page pre-meeting document an advisor uses for a client review: household snapshot, account-by-account breakdown, top Positions, tax-loss candidates, concentration alerts, cash drag. Generated by `services.brief_generator`.

**Collection**
A logical grouping of documents in Asymptote — e.g. all of one Household's brokerage exports plus their meeting transcripts. Each Collection has its own SQLite metadata DB and its own HoldingsStore.
