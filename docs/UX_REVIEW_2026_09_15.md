# Cited-answer workflow review

Audience: agency staff researching internal documents, reviewers checking
briefings, and the developer who uses Clio daily. Direction follows the
existing design context: capable, simple, intelligent; theme-agnostic and focused
on reading. The user prioritized searching agency documents with cited answers.

## Findings before this change

Independent source review scored the workflow **24/40**. These are provisional
heuristic judgments, not user-study results or accessibility certification.

| Heuristic | Score / 4 | Main observation |
|---|---|---|
| System status | 3 | Streaming/indexing states exist; Find progress is timer-driven. |
| Real-world language | 2 | Tokens, similarity scores and SQL metadata compete with the task. |
| User control | 2 | Chat lacks stop and failed-turn retry. |
| Consistency | 3 | Shared controls/themes help; Ask and Find have different scopes. |
| Error prevention | 3 | Invalid actions are disabled; destructive actions confirmed. |
| Recognition over recall | 2 | Answer sources were only a count, with no passage inspection. |
| Efficiency | 3 | History, selections, bulk actions and shortcuts help daily work. |
| Minimalist design | 2 | Completed tool cards overwhelm the answer. |
| Error recovery | 2 | Failed streaming discards partial answers. |
| Help | 2 | Startup guidance exists; evidence review was implicit. |

The automated Impeccable scan of ChatTab, SearchTab and SourcesSidebar returned
no findings. That pattern scan did not detect the workflow problems above.
The main visual problem was repeated containers and tiny technical badges,
not a need to rebrand. Cognitive-load review found three issues: competing
diagnostics, too many simultaneous details, and remembering evidence across tabs.

## Priorities and disposition

| Priority | Problem and user impact | Action |
|---|---|---|
| P1 | A records reviewer cannot inspect the cited passage in place. | Implemented numbered citation controls, passage disclosure, original links and copying with evidence. |
| P1 | A first-time analyst may misunderstand current/all/selected source scope. | Implemented an always-visible Ask scope and direct “Use selection” action. Find scope consistency remains follow-up work. |
| P1 | A daily user cannot stop or retry a failed turn cleanly. | Follow-up: preserve partial output and retry with the original request scope. |
| P2 | Agent diagnostics dominate the response. | Completed activity now collapses; errors remain disclosed. |
| P2 | Find emphasizes scores and simulated progress. | Follow-up: foreground passages and replace timer-driven stages with actual or indeterminate progress. |

Backend inspection also found missing final evidence from agent searches,
ignored streaming reranking, and lost earlier tool results in the streaming
fallback loop. These are corrected. No model-quality score is inferred from
these implementation fixes.

## Validation

- 33 frontend tests pass across the full existing suite and added integration
  checks. Citation review, safe links, sanitized rendering, keyboard focus,
  scope selection and clipboard references are covered.
- 37 targeted backend tests pass across evidence, source selection and cache
  suites, including native and fallback providers with both chat transports,
  reranking, provenance, and quarantined-source refusal.
- Production build passes. Lint has zero errors and five `v-html` warnings;
  the answer renderer remains sanitized and tested.
- Browser verification used fictional fixtures with the real AnswerEvidence
  component. Desktop and 390px layouts and citation disclosure were checked.
  This was not an end-to-end run against a live model or agency collection.

The customer-facing pilot script, fictional corpus, evaluation questions and
expansion priorities are in [AGENCY_PILOT.md](AGENCY_PILOT.md).
