# Ask surface review against Perplexity — September 19, 2026

Audience: the developer and pilot reviewers deciding what the Ask tab should
feel like. Perplexity is the reference for *answer engines*; Clio stays a
grounded assistant over the user's own sources (NotebookLM is still the
reference for the workspace). This note records what people value in
Perplexity, how the Ask tab compared, what shipped, and what is deferred.

## Why people use Perplexity

Taken from its product behaviour and public user feedback, not measured here.

1. **Answer first, sources always in view.** The reply leads with a direct,
   scannable answer; numbered citations sit inline and a strip of source
   cards sits beside the answer. Trust comes from being able to check, fast.
2. **It asks the next question for you.** "Related" suggestions under every
   answer keep a session moving without typing; the empty state offers
   starting points. Most sessions are chains of taps.
3. **Speed you can feel.** A default quick mode answers in one pass; deeper
   modes (Pro Search, Deep Research) are an explicit, visible choice with
   visible steps while they run.
4. **A library, not a chat log.** Threads have titles, can be found again,
   renamed, exported and shared; Spaces group them by topic.
5. **Controls in the composer, not a settings page.** Focus/mode/model
   selection is one tap next to the input.
6. **Honest transparency.** When it searched, what it read, what it could
   not find.

## Where the Ask tab stood (2026-09-19, before this change)

| Perplexity trait | Clio before | Gap |
|---|---|---|
| Inline numbered citations | `[Source N]` chips, clickable, passage review in place | None |
| Sources visible beside the answer | Only inside a collapsed "Review evidence" panel | Sources invisible until expanded |
| Related questions after an answer | None | Sessions stall after each answer |
| Starter questions for a collection | Four hard-coded generic prompts | Not about the user's documents |
| Quick vs deep mode | Model chose per turn; retrieval knobs in a drawer | No one-tap speed/thoroughness choice |
| Visible research steps | "Research activity" with per-tool cards, collapses when done | None |
| Regenerate | Only on cached answers | Fresh answers could not be retried |
| Thread library | Per-collection session list in an icon menu, no rename, no search, no export | Sessions hard to find and reuse |
| Streaming | Word-by-word replay of a finished answer | Time-to-first-token equals time-to-answer |

## What shipped

- **Answer depth.** A Quick / Research control in the composer.
  Quick answers in one provider pass from the retrieved passages and inlined
  tables (large tables remain queryable through the table tools). Research
  is the full agent loop. Quick is the UI default; every quick answer offers
  **Go deeper**, which reruns the question as research. Depth is a request
  field (`ChatRequest.depth`, API default `research`), shows as a badge on
  each answer, and is part of the answer-cache fingerprint.
- **Related questions.** Up to three follow-ups under each answer, written
  by the fast model from the question, the answer and the source names. One
  tap asks one. They stream as their own event after the answer text, ride
  the `done` event, and are stored with cached answers.
- **Starter questions from the sources.** The empty state asks
  `POST /api/chat/starters` for questions the collection can answer, built
  from the overview and the opening passage of a few documents; cached per
  corpus version and selection; quarantined documents are never sampled. The
  generic prompts remain the fallback.
- **Source strip.** Every passage behind an answer as a numbered chip under
  the prose (file, page, passage on hover); a chip opens the passage in the
  evidence panel. Numbers match the inline citations.
- **Regenerate on any latest answer**, not only cached ones.
- **Chat library.** Rename a chat from its title, find a chat when the list
  grows past four, export a chat as Markdown with its evidence.

Validation: 586 backend tests pass (14 new in `tests/test_chat_followups.py`
covering depth, tool restriction, follow-ups, cache carry-over, starters and
failure paths); 59 frontend tests pass (7 new); lint has zero errors and the
five pre-existing `v-html` warnings; the production build passes. No live
model or browser session was exercised in this pass.

## Deferred, in priority order

1. **True token streaming.** The provider layer returns whole completions;
   the stream replays words. Perplexity's felt speed comes from first-token
   latency. Needs streaming support in `ai_service` providers and the tool
   loop, a deliberate change.
2. **Server-side threads.** History is browser storage per collection.
   Sharing a thread, a cross-collection library, or continuity across
   devices needs a `chat_threads` table and endpoints, with the same
   collection access gates.
3. **Share a single answer** as a link (read-only, respecting collection
   access and sensitivity labels).
4. **Answer feedback** (useful / not useful) recorded through `audit.record`
   so pilot reviewers can close the quality loop.
5. **Bare `[N]` citations.** Only `[Source N]` linkifies. A model that drops
   the word "Source" produces plain text; worth linkifying when the number
   is within range and the answer has no other bracketed numbers.
